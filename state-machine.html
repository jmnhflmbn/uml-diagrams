State Machine Diagram

مخطط آلة الحالات

Behavioral Diagram

مقدمة

يُستخدم مخطط آلة الحالات لتوضيح الحالات (States) المختلفة التي يمر بها كائن أو نظام خلال دورة حياته، والانتقالات (Transitions) التي تحدث بينها استجابةً للأحداث (Events) أو عند تحقق شروط معينة.
يعتمد سلوك الكائن على حالته الحالية (Current State) والمدخلات (Inputs) التي يستقبلها؛ إذ تحدد الحالة الحالية والمدخلات كيفية استجابة الكائن وما إذا كان سينتقل إلى حالة أخرى.

العناصر الأساسية للمخطط

العنصر الرمز الشرح
Initial State
نقطة بداية دورة حياة الكائن، وتُمثّل بدائرة سوداء ممتلئة.
State
حالة يكون فيها الكائن خلال فترة معينة، وتُمثّل عادةً بمستطيل ذي زوايا مستديرة. يمكن أن تحتوي على اسم الحالة، وقد تتضمن أنشطة داخلية. يُفضّل أن يُكتب اسم الحالة بصيغة تدل على حالة مستمرة، مثل Processing أو Waiting، أي بصيغة Gerund تنتهي عادةً بـ -ing.
Transition
انتقال من حالة إلى أخرى، ويُمثّل بسهم يوضّح اتجاه الانتقال.
Event / Trigger
حدث يؤدي إلى حدوث انتقال بين الحالات، ويُكتب عادةً على سهم الانتقال. يمكن أن يُكتب بصيغة الماضي المنتهية بـ -ed، مثل Submitted أو Approved.
Guard Condition
شرط يُكتب بين أقواس مربعة، مثل [balance > 0]، ويحدد ما إذا كان الانتقال مسموحًا عند وقوع الحدث.
Action
إجراء يُنفّذ عند حدوث الانتقال، ويمكن كتابته بعد الرمز / على سهم الانتقال.
Entry Action
إجراء يُنفّذ عند الدخول إلى حالة معينة، ويُكتب باستخدام entry / actionName.
Exit Action
إجراء يُنفّذ عند مغادرة حالة معينة، ويُكتب باستخدام exit / actionName.
Do Activity
نشاط يستمر تنفيذه أثناء وجود الكائن في الحالة، ويُكتب باستخدام do / activityName.
Final State
نهاية دورة حياة الكائن في المخطط، وتُمثّل بدائرة سوداء ممتلئة تحيط بها دائرة خارجية.
Composite State
حالة مركّبة تحتوي على حالات فرعية، وتُستخدم لتمثيل سلوك أكثر تفصيلًا داخل حالة رئيسية.
History State
نقطة تتيح العودة إلى الحالة الفرعية السابقة عند إعادة الدخول إلى حالة مركّبة، وتُمثّل بالرمز H أو H* داخل دائرة.

كيفية كتابة Transition

يمكن كتابة الانتقال بالصيغة التالية:
eventName (parameters) [guardCondition] / actionName

ويتكوّن التنسيق من الأجزاء التالية:
Event / Trigger: الحدث الذي يؤدي إلى محاولة الانتقال، مثل Submitted.
Parameters: المعاملات المرتبطة بالحدث، وتُكتب بين أقواس، مثل (userId)، عند الحاجة إليها.
Guard Condition: شرط اختياري يُكتب بين أقواس مربعة، مثل [valid].
Action: إجراء اختياري يُنفّذ عند حدوث الانتقال، مثل saveData().


مثال:
Submitted (userId) [valid] / saveData()

يعني أن الانتقال يحدث عند وقوع الحدث Submitted مع المعامل userId، بشرط تحقق [valid]، ويُنفّذ الإجراء saveData().


ملاحظة: المعاملات Parameters، والشرط Guard Condition، والإجراء Action جميعها اختيارية (Optional)، ويمكن حذفها عند عدم الحاجة إليها.

ملاحظات مهمة عند بناء المخطط

شروط حدوث الانتقال

يحدث الانتقال عندما يقع الحدث (Event) المحدد ويتحقق الشرط (Guard Condition)، إذا كان موجودًا. إذا لم يتحقق الشرط، فلا يُنفّذ الانتقال المرتبط به.

أولوية الانتقالات داخل Composite State

إذا كان الكائن داخل Composite State، ووجدت انتقالات متعددة مرتبطة بالحدث نفسه في مستويات متداخلة، فتكون الأولوية للانتقال الأكثر داخلية (Innermost Transition) المؤهل للتنفيذ، قبل الانتقالات المعرّفة في الحالات الخارجية.

مكان كتابة الإجراء وترتيب التنفيذ

يمكن كتابة الإجراء على سهم الانتقال باستخدام / actionName، أو داخل الحالة باستخدام entry أو exit.
يختلف توقيت التنفيذ وترتيبه حسب موضع الإجراء؛ فإجراء الانتقال يرتبط بحدوث الانتقال، بينما entry يُنفّذ عند الدخول إلى الحالة، وexit عند مغادرتها.

تنفيذ الأنشطة الداخلية

يمكن أن تتضمن الحالة Do Activity، وهو نشاط يستمر أثناء وجود الكائن في الحالة. وعند وجود أكثر من نشاط أو سلوك مستقل مطلوب تنفيذه بالتوازي، فلا يُفترض ترتيب تنفيذي ثابت بينها ما لم يحدده النموذج.
